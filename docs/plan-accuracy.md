# 사건 분류 정확도 계획

작성일: 2026-11-04. 사용자 결정: 시나리오 개수보다 정확도를 우선한다. 서비스 실행 중에 외부 AI API를 부르지 않는다. 같은 사연은 같은 사건·죄명·유무죄를 받는다.

## 원칙

- **판단과 표현을 나눈다.** 어떤 사건인지·죄명·유무죄·처분은 고정하고, 변화는 같은 사건 안의 표현(주문·변명·재판부 한마디)에서만 준다.
- **틀린 구체 죄명보다 일반 혐의가 낫다.** 애매하면 '생활 배려 의무 소홀 혐의'로 보류하거나 이용자에게 묻는다.
- **측정한 것만 개선이라고 말한다.** 아래 시험지의 숫자가 나아지지 않으면 넣지 않는다.

## 지표

| 지표 | 뜻 | 방향 |
|---|---|---|
| 오답률 | 정답이 있는 사연에 다른 구체 죄명이 붙은 비율 + 정답이 없는 사연(일반 분쟁)에 구체 죄명이 붙은 비율 | 가장 중요. 낮을수록 좋다 |
| 적중률 | 정답이 있는 사연에 정답 사건이 나온 비율 | 높을수록 좋다 |
| 보류율 | 정답이 있는 사연이 일반 혐의로 빠진 비율 | 낮을수록 좋지만 오답보다는 낫다 |

## 단계

1. **시험지(평가셋) 분리** — 키워드를 보지 않고 쓴 사연에 정답 사건을 붙인다. 조정용(dev)과 최종 확인용(test)으로 나누고, 기준값은 조정용으로만 정한다. 최종 확인용 숫자로 보고한다.
2. **Top-3 후보 + 애매할 때만 묻기** — 1등이 확실하면 바로 판결하고, 격차가 작으면 이용자에게 후보 3개와 '해당 없음'을 보여 준다. 화면 변화가 있으므로 모양을 사용자에게 먼저 보여 준다.
3. **글자 조각 유사도** — 글자 2~3개 조각(n-gram)과 TF-IDF 가중치, 코사인 유사도로 키워드 일치를 보강한다. 유사도 컷·마진 컷은 조정용 시험지에서 오답률이 가장 낮은 값으로 정한다.
4. **규칙 재정렬** — 후보를 뽑은 뒤 주체(제가/내가), 부정(안 ~않았는데), 불만이 아닌 문장(고마웠어요)을 확인해 감점·보류한다. '후보 뽑기 → 규칙 확인 → 컷'의 3단계 구조로 정리한다.

### 봉인 시험지 (최종 확인)

`backend/tests/eval/holdout-set.cjs` 301개(그중 152개가 함정 문장: 내가 한 일·오해·칭찬·사람 탓 아님). 규칙과 키워드를 만든 뒤에 처음 열었고, 앞으로도 문항을 보고 맞추지 않는다. `node backend/scripts/eval-matching.cjs holdout`.

|---|---|---|---|---|

예시 사연 유사도는 봉인 시험지에서 처음으로 큰 효과를 보였다(적중 34.2→57.7%, 오답 27.2→24.3%). 예시 문장은 키워드·시험지를 보지 않고 썼고, 시험지와 겹치는 문장이 없음을 확인했다. 사연 하나당 계산은 약 5ms(첫 호출 때 색인 생성 약 0.1초).

해석(유사도 이전): 나빠진 곳은 없지만 개선 폭은 확인용 시험지(22.4→14.3%)보다 훨씬 작다. 봉인 시험지는 문장이 더 다양해서, 문장 모양 규칙은 '오해였음'·'칭찬'은 일부 잡지만 '내가 한 일'은 거의 잡지 못했다(오답 26→25). 규칙만으로는 한계가 뚜렷하며, 다음 개선은 시나리오별 예문을 늘린 유사도·분류 모델(향후 AI 기술 항목)이나 2단계(이용자에게 묻기)에서 나올 가능성이 크다.

관찰: 보류된 사연 대부분은 **후보가 하나도 없었다**(키워드가 전혀 맞지 않음). 지금 방식에서 Top-3를 물으면 313개 중 3개 정도만 구제된다. 그래서 2단계(묻기)는 3단계(유사도)로 후보를 만든 뒤에 다시 잰다.

## 향후 반영: 실제 AI 기술 (아직 하지 않음)

실제 이용자 사연에서 오분류 사례가 충분히 모이기 전에는 도입하지 않는다. 제가 쓴 예문만으로 학습하면 그 말투에만 맞춰진 모델이 되기 쉽다. 어느 쪽이든 외부 API 없이 앱 안에서 돌고, 같은 입력에 같은 결과를 내야 한다.

| 기술 | 쉬운 설명 | 장점 | 부담·위험 | 착수 조건 |
|---|---|---|---|---|
| 작은 분류 모델 (로지스틱 회귀 등, 글자 조각 입력) | 예문 수천 개로 "이런 글자 조각이 나오면 이 사건"을 미리 학습해 숫자표로 저장 | 가볍다(수백 KB~수 MB), 결과 고정, 서버 비용 거의 없음 | 학습 데이터 편향, 모델이 왜 그렇게 골랐는지 설명이 어려움 | 실제 사연을 고쳐 쓴 예문이 시나리오당 10개 이상, 시험지에서 3단계보다 오답률이 낮을 때 |
| 문장 임베딩 (한국어·다국어 소형 모델) | 문장의 뜻을 숫자 목록으로 바꿔 비교. "답장을 안 해"와 "연락이 없어"를 가깝다고 본다 | 표현이 달라도 뜻으로 잡는다 | 모델 파일 100MB 안팎. 현재 무료 서버(메모리 512MB)에서 느려지거나 메모리가 부족할 수 있음. 서버 사양 변경이 필요할 수 있다 | 위와 같고, 서버 사양·응답 시간 측정을 먼저 한다 |
| 두 방식 결합 | 임베딩으로 후보를 뽑고 규칙·분류 모델로 확인 | 정확도가 가장 높을 가능성 | 복잡도·유지보수 증가 | 위 둘 중 하나가 효과를 보인 뒤 |

데이터 수집 원칙: 운영 DB의 사연은 고지문 제2조 때문에 학습·저장소로 옮기지 않는다. 사용자가 동료에게 받은 오분류 사례를 본인 동의 하에 고쳐 써서 넣는다.
